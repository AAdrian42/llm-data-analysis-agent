# 用户测试与提效实验方案

## 实验目的

验证数据分析 Agent 是否真正降低标准查数任务的完成时间，同时观察错误率、口径理解和使用体验。实验完成前，不在简历中宣称“提效 50%”。

## 参与者

- 5-8 名具有运营、风控或基础数据分析经验的参与者。
- 至少一半不熟悉 SQL，用于观察目标用户体验。
- 参与者不得提前看到标准答案。

## 对照设计

采用被试内交叉实验，每名参与者完成两组难度相近的任务：

- 对照组：使用 Excel、现有报表或手写 SQL。
- 实验组：使用 LLM 数据分析 Agent。

为降低学习效应，一半参与者先使用对照工具，另一半先使用 Agent。

## 任务示例

1. 计算 2025 年各产品审批通过率并找出最高产品。
2. 分析不同 DTI 区间的违约率。
3. 绘制月度申请量趋势并描述变化。
4. 找出平均贷款金额最高的前 5 个地区。
5. 对比不同信用等级和贷款期限的违约率。

## 记录指标

- 任务完成率：是否得到正确结果。
- 首次正确率：是否无需修改即可得到正确结果。
- 完成时间：从看到任务到提交结果的秒数。
- 口径错误率：是否使用错误分母、过滤条件或时间范围。
- 交互次数：修改问题、重新查询和求助次数。
- 主观评分：易用性、信任度和继续使用意愿，采用 1-5 分。

## 提效计算

```text
提效比例 = (对照组中位耗时 - Agent组中位耗时) / 对照组中位耗时
```

同时报告完成率和正确率，避免通过牺牲质量换取速度。样本较小时使用中位数，并展示每个任务的原始数据。

## 成功标准

- Agent 组任务完成率不低于 90%。
- Agent 组正确率不低于对照组。
- 标准任务中位耗时至少下降 30%。
- 严重指标口径错误为 0。
- 平均信任度不低于 4/5。

## 访谈问题

- 哪一步最节省时间？
- 哪些结果仍然需要人工核验？
- SQL、指标口径和样本量是否增强了信任？
- 哪些问题表达方式系统无法理解？
- 在什么情况下不愿意使用该工具？

## 输出物

- 匿名任务明细表。
- 每项任务的耗时、正确率和完成率对比。
- 失败问题分类与改进优先级。
- 经验证后可以写入简历的真实提效数字。
