# LLM 数据分析 Agent PRD

## 1. 用户问题

业务人员经常需要临时查看某个指标、拆分一个维度或制作一张图。传统流程通常依赖分析师理解需求、确认口径、写 SQL、检查结果并制作图表，简单问题也可能排队等待。另一方面，直接让大模型生成 SQL 容易出现字段幻觉、口径不一致和越权查询。

## 2. 产品目标

让非技术用户能够用自然语言完成标准化的自助分析，同时保证指标有统一口径、查询可追溯、结果可复核、权限边界清晰。

## 3. 目标用户

- 业务运营：快速查看趋势、分组和 Top N。
- 风控策略人员：分析客群、通过率、违约率和审核效率。
- 数据分析师：减少重复取数，并复核系统生成的 SQL 和口径。

## 4. 核心流程

1. 用户输入自然语言问题。
2. Agent 识别指标、维度、筛选条件和图表需求。
3. 语义层校验字段与指标口径。
4. SQL 编译器生成只读查询，安全层拦截危险语句。
5. DuckDB 执行查询，Pandas 检查结果质量。
6. 图表模块选择可视化，回答模块总结关键结果。
7. 页面展示指标口径、SQL、执行轨迹和风险提示。

## 5. MVP 功能

- 8 个标准指标、10 个分析维度、常见筛选和 Top N。
- 柱状图、折线图、热力图和指标卡。
- 本地规则规划器与 GPT/Claude Function Calling 双模式。
- 只读 SQL、安全限制、错误恢复和审计日志。
- 问题样例、结果导出和离线评测页。

## 6. 成功指标

- 结构化计划准确率：目标不低于 90%。
- 查询执行成功率：目标不低于 95%。
- 指标口径正确率：目标 100%。
- 危险 SQL 拦截率：目标 100%。
- 用户任务完成时间：后续通过至少 5 名目标用户对照实验测量。

## 7. 非目标

- 不允许模型自由访问任意数据库或文件系统。
- 不支持未经登记的指标和字段。
- 不把自然语言结论当作正式经营报表。
- 不宣称未经实验验证的效率提升。

## 8. 验收标准

- 无 API Key 时所有示例问题均可运行。
- 每次回答展示指标定义、实际 SQL 和数据行数。
- SQL 注入、DDL/DML、外部文件读取和多语句均被拦截。
- 空结果、小样本和缺失值能够触发明确提示。
- 离线评测和自动化测试通过。
